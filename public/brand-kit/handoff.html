Latest motion decisions — essential

Floating banner: Free System outlined, Apply Black filled, equal columns. 420px maximum, 16px corners. 320ms vertical slide. Entrance cubic-bezier(.4,0,.6,1); exit cubic-bezier(.4,0,1,1). No opacity fade. Keep it rendered until the exit finishes; disable interaction immediately; cancel stale cleanup on reversal. Hero/offer release: 80% of BOTH page buttons passes header bottom. Hide when a section's first CTA touches the resting bottom of the banner. Return after offers clear; hide through the final CTA/footer. Same rule desktop/mobile.

Founder priority: STABILITY OVER EASING on both mobile and desktop. The owner confirmed the mobile sticky implementation has zero lag on their phone and requested the same behavior on desktop. All widths now use a zero-height sticky tip at the viewport center and an upward-painted fill clipped to the rail. There is no scroll timeline, scale animation, easing or settling loop. On iOS the sticky offset subtracts --page-scroll-padding-top. Reduced motion retains sticky geometry; unsupported browsers use direct JS tracking. Do not restore the previous 55ms desktop easing or the sampled view-timeline implementation. Desktop upward wheel reversals from the rail end and mobile touch restarts passed with animation frames paused. Marker appearance and activation points are unchanged. Physical desktop feedback on this latest revision is still pending.

System: no vertical line; inactive cards .38 opacity. Compact active phase labels return to the phase list; a deliberate swipe/wheel/key resumes reading. Programmatic scrolling and resize must not reset that selected phase. Rooms: desktop grid; compact manual scroll-snap carousel; no autoplay.

Safari limitations and history worth preserving

The owner repeatedly reported text reappearing in the status-bar area during rapid scrolling. Current iOS solution uses a fixed native .page-viewport with a stationary clip; page-scroll.js selects the active scroller. Never bypass this abstraction in new scroll/anchor/modal work. Avoid per-scroll JS clipping. Content fades into black near the top using a gradient, not visible cloud blur or particles.

Attempts to extend the narrow header glass into physical Safari clock/status-bar chrome were unsuccessful. The current implementation retains this visible boundary; full extension remains unresolved. Do not claim this has been solved. Root canvas/glass continuation rules remain in code; they are not proof of physical browser-chrome coverage. iOS contained scrolling can keep browser controls visible. Physical Safari verification is still required for changes here.
